# Factory GitHub App setup

The Factory App creates PRs, pushes updates, and replies to issues under its own
`<app-slug>[bot]` identity. The [review workflow](pr-review.md) uses
`github-actions[bot]`, allowing it to approve the App's PRs without violating
GitHub's self-approval restriction. Git commit author names do not change these
API identities.

App-created PRs and subsequent App-authenticated pushes trigger matching PR
workflows without the manual approval required for events generated by
`GITHUB_TOKEN`. Independent repository or environment approval policies still apply.

## Configure the App

1. [Register a GitHub App](https://docs.github.com/en/apps/creating-github-apps/setting-up-a-github-app/creating-a-github-app)
   with the repository permissions needed by your workflows:

   | Permission | Access | Used for |
   |---|---|---|
   | Contents | Read and write | Reading code and pushing branches |
   | Pull requests | Read and write | Creating and updating PRs |
   | Issues | Read and write | Triage, labels, and issue replies |
   | Workflows | Read and write for issue implementation | Changing `.github/workflows/` files |

   Metadata read access is included automatically. A webhook is not needed for
   this token-only integration.
2. Install the App on this repository.
3. Save its Client ID as the repository Actions variable `FACTORY_CLIENT_ID`.
4. Generate a private key and save its PEM contents as the repository Actions
   secret `FACTORY_PRIVATE_KEY`.

After changing App permissions, approve the updated installation access under
**GitHub Settings → Applications → Installed GitHub Apps → Configure**. Updating
the App definition alone does not grant new permissions to an existing installation.

## Use the App in a workflow

For [PR creation](create-pull-request.md), generate a token before checkout and
use it for checkout's persisted push credentials:

```yaml
- name: Create PR App token
  id: pr-app-token
  uses: actions/create-github-app-token@v3
  with:
    client-id: ${{ vars.FACTORY_CLIENT_ID }}
    private-key: ${{ secrets.FACTORY_PRIVATE_KEY }}
    permission-contents: write
    permission-pull-requests: write

- name: Check out repository
  uses: actions/checkout@v6
  with:
    token: ${{ steps.pr-app-token.outputs.token }}
```

Request the permissions each job needs: triage uses `permission-contents: read`
and `permission-issues: write`; implementation also requests
`permission-pull-requests: write`, `permission-contents: write`, and
`permission-workflows: write`. Requested permissions must be granted to the
installation. Workflow-write access is required when pushing workflow changes
to a PR branch, before merge; the token-generation input must already be on the
default branch before Factory can implement such an issue.

Set these variables on the AI invocation, keeping any Git author/committer variables:

```yaml
GITHUB_TOKEN: ${{ github.token }}
COPILOT_GITHUB_TOKEN: ${{ github.token }}
GH_TOKEN: ${{ steps.pr-app-token.outputs.token }}
```

`gh` prefers `GH_TOKEN`, so GitHub operations use the App identity. Explicit
`COPILOT_GITHUB_TOKEN` keeps model requests on the built-in token. For PR creation,
the built-in token only needs:

```yaml
permissions:
  contents: read
  copilot-requests: write
```

The [token action](https://github.com/actions/create-github-app-token) defaults to
the current repository and revokes its short-lived token at the end of the job.
Generate a fresh token in each job that needs it.

## Review identity and approvals

Keep the review workflow's built-in token and `github-actions[bot]` verification
filter, and enable **Settings → Actions → General → Workflow permissions → Allow
GitHub Actions to create and approve pull requests**.

Using the same App identity to create and review PRs reintroduces the self-approval
problem. Existing PRs retain their original author; create a new PR with the App
to test approval. App-based PR creation has been tested successfully; approval
testing is tracked in the [review example](pr-review.md).
